This is an explicit rejection from the external AGO service, not a successful

The four blank grey rows are unused guess slots (`GuessRow`), not missing answer

## Client correction

- On an explicit retry after a media error or rejected `play()`, call `load()`
  before `play()` so the browser performs a fresh resource selection/request.
  Previously the button only called `play()` again on the failed resource.
- Seek after metadata is available and catch seek errors. A failed or not-yet-
  loaded resource should not throw outside the player's error handling.
- Pause and clear the playing state on errors; expose an accessible retry label
  and an alert that does not blame the user's connection.
- Ignore stale playback promises after a newer attempt or sample change.
- Keep completed progress at the end of the excerpt when the browser emits
  another `timeupdate` for the seek back to its start.

No catalogue URL, sample identity, selected answer, rotation, score, persisted
guess, backend, or challenge type changed. There is no visual fallback.
